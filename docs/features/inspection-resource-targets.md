# 자산 기반 정기 자원 점검

서버 점검의 `서버리스트`를 `자원 점검`으로 변경했다. 자산에 등록된 서버 중 정기 점검할 대상을 한 번 선택하고 매월 재사용한다. 서버명·IP를 점검 화면에서 별도로 등록하거나 수정하지 않는다.

기존 `요약` 메뉴는 `자원 점검`에 통합했다. 정기 대상 설정은 대화상자로 분리하고, 기본 화면은 모든 측정 결과와 결과가 없는 정기 대상을 한 목록에서 확인한다. 이상 항목·결과가 없는 대상·자산 미연결 항목을 상단 카드로 필터링한다. Excel 업로드·삭제, 측정값 검색·정렬, 서버 상세·조치·추이 조회를 같은 화면에서 수행한다. 기존 `/inspection/health-summary` 링크도 통합 화면으로 연결한다. 설계는 [자원 점검 화면 재설계](inspection-resource-redesign.md)를 참고한다.

월 안에서 과거 업로드를 선택할 때는 GET `/inspection-resources`의 `source_id`를 사용한다. 다른 월의 자료는 거부하며 별도 선택이 없으면 최신 자료를 조회한다. 조회 응답의 `sources`는 해당 월의 자료만 최신순으로 제공한다. 이 선택은 월간 보고서의 최신 자료 자동 선택을 변경하지 않는다.

- `점검 대상 선택`: 기존 서버 자산을 검색해 추가·제외한다. 선택은 팀 공용이며 서버 점검 권한으로 관리한다. 외부망 읽기 전용 정책은 그대로 적용한다.
- 월별 화면: 기본으로 해당 월의 최신 업로드 자료를 사용한다. 전월 자료도 해당 월의 최신 자료를 사용하며 다른 달로 대체하지 않는다. 자료가 없는 대상도 목록에 남는다.
- 자산의 호스트명과 점검 자료의 호스트명이 유일하게 일치하면 자동 연결한다. 대소문자·앞뒤 공백·마지막 마침표는 정규화한다. IP가 변경되거나 공유되어도 고유한 호스트명이 일치하면 연결한다. 자원 점검과 월간 보고서는 같은 로직을 사용한다.
- 호스트명이 다르면 자산에서 수정한다. 동일 IP의 자산이 하나인 경우 수정할 자산을 찾는 참고 정보와 `자산 확인` 링크를 제공한다. IP만으로 연결하지 않는다. 자산 수정 후 돌아오면 다시 조회하며, 새로고침도 제공한다. 호스트명이 중복·누락되거나 자산이 삭제된 경우 자동 연결하지 않는다.
- 자동 연결되지 않은 예외 항목은 `이번 달 연결 자산`에서 직접 선택하거나 해제한다. 선택은 현재 사용자·월·업로드 자료별 브라우저 메모리에만 두며 DB나 브라우저 저장소에 매핑 규칙을 쓰지 않는다. 전체 새로고침 시 임시 선택은 사라진다. 자원 점검과 보고서 작성 화면 사이에서는 같은 자료의 임시 선택을 공유한다.
- 보고서를 저장하면 선택 결과는 그 보고서의 스냅샷에만 남는다. 해당 보고서의 같은 자료를 갱신할 때는 유지할 수 있고 명시적으로 해제할 수 있다. 새 업로드 자료나 다음 달에는 재사용하지 않는다. 호스트명이 정상화되면 자동 연결이 우선한다.
- 기존 영구 수동 연결 기록은 보존하지만 새 조회·초안·자료 갱신에는 사용하지 않는다. 연결할 자산이 없는 항목도 미연결 상태로 보고서에 포함한다. 저장된 보고서의 스냅샷은 자동 변경하지 않는다.
- 정기 대상에 연결되지 않은 업로드 자료도 기본 결과 목록에서 확인한다. 호스트명이 중복된 측정 행은 자동 연결하지 않으며, 사용자가 각 행의 예외 연결을 지정할 수 있다.
- 현재 대상 선택은 월과 무관한 공용 설정이다. 대상 제외는 원본 자료·연결 기록·확정 보고서를 삭제하지 않는다. 지난달을 조회해도 현재 대상 목록을 기준으로 보여주며, 제외한 서버의 원본 자료도 전체 결과 목록에서 확인할 수 있다.

설정은 `app_settings`의 `inspection_resource_targets` 문서에 자산 ID와 버전만 저장한다. 조회 시 현재 자산 정보를 가져오며, 삭제된 자산은 제외할 때까지 표시한다. 버전 비교로 동시 편집 충돌을 감지한다.

API는 `/inspection-resources?month=YYYY-MM`, `/inspection-resources/targets`(GET/PUT)이다. 예외 연결은 `/inspection-resources/preview`(POST) 및 보고서 미리보기의 `mappings`에 해당 자료 ID와 함께 전달한다. 자원 미리보기 API는 매핑·원본 자료·정기 대상 설정을 저장하지 않는다. 기존 영구 저장 API `/inspection-resources/{source_id}/mappings`는 410으로 안내한다. 기존 화면 경로 `/inspection/health-servers`는 유지하고 시작 시 기존 메뉴 이름을 변경한다.

검증: 정기 대상·연결·권한·동시 편집·기록 보존·업로드 자료 선택 테스트 14개를 추가했다. 기존 월간 점검 및 보고서 테스트와 함께 실행한다.

```sh
docker compose run --rm --no-deps -v "$PWD:/workspace:ro" -w /workspace -e INSPECTION_TEST_MONGO=1 backend python -m unittest discover -s tests -p 'test_*inspection*.py' -v
```

실행 중인 Docker 컨테이너는 소스 코드를 마운트하지 않으므로 적용하려면 백엔드·프런트엔드 이미지를 재빌드해야 한다.
