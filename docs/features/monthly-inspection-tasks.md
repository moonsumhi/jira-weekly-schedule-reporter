# 월별 서버 점검 작업

## 사용 흐름

- 서버 점검 → **월간 작업**(`/inspection/tasks`)에서 점검 월을 선택한다. 보고서 업로드 전에도 사용 가능하다.
- **작업 추가 → 기존 이슈 연결**: 프로젝트·이슈를 고르고 등록 서버 자산을 여러 대 선택하거나 공통 작업을 지정한다.
- **작업 추가 → 새 작업 등록**: 프로젝트·제목·담당자·작업 예정일을 입력한다. PM TASK가 생성되며 예정일이 시작일/마감일로 반영된다. 예정일 기본값은 해당 월의 점검일이다.
- 스케줄 관리 보드·백로그의 **이슈 추가 → 작업 대상 서버**는 점검 여부와 관계없이 자산의 운영 이력과 연결한다. **서버 점검에 추가**를 체크하면 같은 대상 서버와 점검 월(기본 이번 달)로 월간 작업에도 연결한다. 서버를 고르지 않은 점검은 공통 작업을 명시적으로 선택한다. 입력한 이슈 시작일·마감일은 그대로 사용한다.
- PM 이슈 상세의 **서버 점검 · 건수** 버튼에서 연결된 작업 요약, **작업 추가 / 월간 작업 열기**를 사용할 수 있다. 자산에서는 **운영 이력** 탭에 문서·이슈·운영 메모와 함께 연결된 점검 기록을 표시한다.
- 월별 목록에서 PM 이슈 상태를 변경하거나 상세를 열어 댓글·첨부 등 기존 기능을 사용한다.
- 지난달 미완료는 월이 바뀌어도 표시된다. 계속 진행할 작업은 그대로 두고, 이월 또는 제외할 작업은 사유를 남긴다.
- 다음 점검으로 이월하면 다음 달 회차가 생긴다. 오래된 회차는 이번 달로 가져온다. 원본 PM 이슈와 마감일은 유지된다.
- 점검 대상 제외는 PM 이슈를 삭제하지 않는다. 같은 월에 다시 연결하면 이전 제외 이력을 보존하며 복구한다.

## 화면 구성

- 기본 탭은 미완료이며 이전 달 미완료를 별도 그룹으로 먼저 표시한다. 완료·전체·이월/제외 탭으로 전환 가능하다.
- 점검 월과 예정일, 전체 진행률을 한 영역에서 확인한다. 월 선택은 한국어 연도/월 선택기를 사용한다.
- 작업 앞의 원을 눌러 완료 처리한다. 현재/미래 회차의 상태 변경은 알림의 되돌리기로 복원할 수 있다. 지난 회차를 완료하면 기존 정책대로 완료 이력을 보존한다.
- 작업 검색과 내 작업 필터를 조합할 수 있다. 검색 결과 없음과 미등록, 미완료 없음 상태를 구분한다.
- 이슈·서버 상세에서 이동하면 해당 이슈·서버에 연결된 작업만 조회한다. 상단에 조회 범위를 표시하고 **월간 전체 작업 보기**로 조건을 해제할 수 있다. 해당 이슈의 연결이 없을 때는 월 전체가 비었다는 의미와 구분해 안내한다. 사이드바에서 월간 작업으로 다시 진입하면 링크에서 적용했던 월과 필터를 초기화한다.
- 이슈 생성과 점검 연결을 마친 알림에는 등록한 월을 표시하며 **월간 작업 보기**로 방금 연결한 이슈를 바로 확인할 수 있다.
- 등록창은 작업 정보와 대상 서버 선택을 나란히 배치한다. 작은 화면에서는 전체 화면으로 열리며 내용만 스크롤되고 저장 버튼은 하단에 유지된다.
- 이미 해당 월에 연결된 이슈는 선택 목록에 표시하고 재선택을 막는다. 서버 검색 결과를 체크해서 여러 대 선택하며 선택한 서버를 별도로 확인·제거할 수 있다.
- 등록을 마치면 등록한 월의 전체 목록으로 이동한다. 이월/제외 확인창에는 작업명과 실제 이월 대상 월을 표시한다.
- 이슈 상세 탭 옆에 작은 연결 건수 버튼을 표시한다. 요약창은 본문 위치를 바꾸지 않으며 미완료 작업 우선 최대 4건만 미리 보여주고 반복되는 이슈 제목 대신 대상 서버를 표시한다. 자산의 운영 이력은 회차별 점검 월·작업 제목·이슈 번호·상태·담당자를 표시한다. 클릭하면 점검 기록과 연결된 이슈를 팝업에서 확인하며 자산 화면을 유지한다. **월간 작업에서 관리**로 이동할 때만 기존 자산 상세창을 닫는다.

## 권한과 데이터

- 모든 점검 API에 `server_check` 또는 관리자 권한이 필요하다.
- 프로젝트 멤버가 조회·변경할 수 있는 이슈만 연결/조회한다. 관리자는 전체 프로젝트에 접근한다.
- 서버 선택 API는 서버 점검 권한에 필요한 최소 자산 정보(이름, IP, 자산명, 상태)를 제공한다. 전체 자산 상세 페이지는 기존 `asset` 권한을 따른다.
- 자산 MongoDB ID를 저장하며, 여러 대 선택 가능(최대 100대). 삭제/없는 자산 신규 연결 및 중복 ID를 거부한다.
- 등록 당시 자산 이름/IP를 보존한다. 현재 회차는 최신 정보를 표시하고, 과거 회차는 당시 정보를 표시한다. 삭제된 자산/이슈도 기존 기록에서 식별할 수 있다.
- 이슈 제목·상태·담당자는 PM을 기준으로 한다. 이월/제외 회차에는 당시 이슈 정보가 저장된다.
- DONE만 완료로 집계한다. IMPLEMENTED는 미완료이다. 지난달 완료 이력은 이슈가 다시 열려도 유지한다. 현재/미래 회차는 다시 열면 미완료로 돌아간다.
- `inspection_tasks`에 이슈 ID를 `_id`로 한 문서를 저장하고 `occurrences` 배열에 회차를 저장한다. 버전 조건부 갱신으로 중복 등록과 이월 충돌을 방지하며, 이월 양쪽 회차는 한 번에 저장된다.
- 새 이슈 생성 후 점검 연결에 실패하면 등록 다이얼로그가 생성된 이슈 ID를 보유한다. 다이얼로그를 유지한 채 다시 저장하면 동일 이슈로 재시도한다. 닫았다면 기존 이슈 연결에서 생성된 이슈를 선택한다.
- 일반 이슈 생성창에서도 연결 실패 시 생성된 이슈를 보존하고 입력한 이슈 정보는 잠근다. 대상 정보를 수정하여 **점검 연결 재시도**하거나 **연결 없이 닫기**를 사용할 수 있다. 응답 유실 시 같은 이슈·월·대상이 저장되어 있는지 확인하며, 저장 전 삭제된 자산을 검사한다.

## 일정과 알림

- 기본 점검일: 매월 셋째 목요일(KST).
- 기존 홈 D-Day의 `서버 점검일 YYYY-MM` 변경일을 사용한다.
- 홈에 내 미완료 작업 수를 표시한다. 점검일이 지나도 미완료가 있으면 표시를 유지한다.
- 09:00 KST에 점검 3일 전/당일 담당자별로 미완료 이슈를 묶어 앱 내 SYSTEM 알림을 생성한다. 지난달 미완료도 포함한다.
- 여러 worker 또는 재시작으로 반복 실행되어도 점검일·알림 시점·담당자별 결정적 `_id`로 중복을 방지한다. 메일/외부 메시지 발송은 없다.

## 검증 및 반영

백엔드 시작 시 월간 작업 메뉴와 조회 인덱스를 멱등 추가한다. 신규 컬렉션이므로 기존 보고서/조치 내역 마이그레이션은 필요 없다. 실행 중인 Docker 서비스는 소스를 마운트하지 않으므로 새 코드 사용에는 백엔드·프런트엔드 재빌드/재시작이 필요하다.

```sh
# 프로젝트 루트에서 실행. 임시 컬렉션만 생성하고 테스트 종료 후 삭제한다.
docker compose run --rm --no-deps -v "$PWD:/workspace:ro" -w /workspace -e INSPECTION_TEST_MONGO=1 backend python -m unittest discover -s tests -p test_inspection_tasks.py -v

# frontend/optool에서
npm run build
```

정기 작업 자동 생성과 Excel 결과에서 작업 후보 추출은 이번 구현 범위에 포함하지 않는다.
