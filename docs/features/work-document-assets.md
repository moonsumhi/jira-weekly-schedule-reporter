# 작업 관리 문서 ↔ 서버 자산

- 작업 관리의 모든 문서(작업계획서 서비스 / 서비스 외, 작업결과서, 반입신청서 등) 작성·Import 후 저장·수정 화면의 `대상 서버 연결`에서 호스트명, IP, 서버명으로 등록 서버를 검색한다. 한 문서에 최대 100대까지 연결하며, 서버 없는 문서도 저장할 수 있다.
- 상세 화면의 `대상 서버`에서 연결된 자산으로 이동한다. 자산 상세의 `운영 이력` 탭에는 문서 종류, 제목, 작업일 또는 신청일, 작성자, 문서 등록일이 표시되며 클릭하면 페이지 이동 없이 해당 문서 팝업을 연다. 닫기·뒤로 버튼·Esc로 팝업만 닫고 기존 자산, 탭, 이력 스크롤을 유지한다. 팝업에서도 수정·내보내기를 사용할 수 있으며 저장하면 자산 이력을 갱신한다.
- 기존 문서는 수정 화면에서 연결한다. 기존 본문에 적힌 호스트명으로 자동 연결하지 않으며, 연결 선택으로 본문·원본 파일·내보내기 양식을 덮어쓰지 않는다.
- 연결 변경은 문서 저장 시 본문과 같은 버전 조건으로 적용된다. 저장 전 닫기 확인과 버전 충돌 시 입력 유지도 적용된다.
- 삭제된 자산은 기존 연결과 이름을 보존하고 삭제 표시한다. 새 연결은 차단하며 기존 연결을 해제할 수 있다. 삭제된 문서는 자산 이력에서 제외한다.
- 연결 가능 여부는 문서 제목이 아닌 `menu=Job`(대소문자 무관)으로 판단한다. 이름을 바꾸거나 작업 관리에 새 양식을 추가해도 연결할 수 있다. 다른 메뉴의 양식과 삭제된 양식은 연결 및 자산 이력에서 제외한다. 기존 자산 연결 데이터는 그대로 사용하며 별도 이관이 필요 없다.

## 자산 운영 메모

- 자산 상세의 `운영 이력 → 메모 추가`에서 내용(최대 5,000자)을 바로 남긴다. 별도 제목이나 작업 관리 문서 생성은 필요 없다. 일자는 한국 시간 기준 오늘로 채우며 과거 날짜로 바꿀 수 있다.
- 문서·서버 점검·운영 메모는 등록일 최신순으로 한 목록에 표시한다. 운영 메모에는 일자·작성자·등록 시간과 수정 여부가 표시되며, 클릭하면 전체 내용을 팝업에서 확인한다. 내용은 서식 없는 텍스트로 저장·표시한다.
- 자산 권한 또는 관리자는 조회·작성할 수 있다. 작업 관리 권한이 없는 사용자에게는 문서와 문서 건수를 응답에 포함하지 않는다.
- 작성자 또는 관리자만 수정·삭제한다. 수정·삭제는 버전 충돌을 확인하며 삭제는 논리 삭제한다. 삭제된 자산의 이력은 조회할 수 있고 운영 메모 변경은 제한한다.
- 저장 실패·버전 충돌 시 입력 내용을 유지하며, 등록 요청 ID로 응답 유실 후 재시도에 따른 중복 등록을 막는다. 작성 중 닫기 확인과 늦게 도착한 조회 응답 무시도 적용한다.

## 서버 점검 이력

- 자산 상단의 별도 서버 점검 메뉴를 `운영 이력` 탭으로 통합한다. 이 자산이 대상으로 지정된 월별 작업을 점검 월·이슈 제목·상태·담당자와 함께 표시한다. 점검 작업 등록은 서버 점검의 월간 작업 화면이나 이슈에서 진행한다.
- 항목 클릭 시 페이지 이동 없이 점검 기록 팝업을 열고 이월·제외 사유 및 대상을 확인한다. `연결된 이슈 보기`도 팝업으로 열며 닫으면 기존 자산과 이력을 유지한다. 명시적인 `월간 작업에서 관리` 버튼만 월간 작업 화면으로 이동한다.
- 동일 이슈의 월별 회차를 각각 보관하고 과거 완료·이월·제외 기록은 월간 작업과 동일한 스냅샷 규칙을 따른다. 이슈나 자산이 삭제되어도 기록을 보존한다. 대상이 없는 공통 작업이나 다른 회차에서만 이 자산이 지정된 기록은 포함하지 않는다.
- 서버 점검 권한과 해당 프로젝트 멤버십을 모두 확인한 후 전체 건수와 페이지를 계산한다. 관리자는 전체 연결 기록을 볼 수 있다.

## 스케줄 이슈와 서버 연결

- 보드·백로그의 이슈 생성 창에서 `작업 대상 서버 (선택)`를 호스트명·IP·서버명으로 검색해 최대 100대까지 연결한다. 서버를 선택하지 않아도 이슈를 생성할 수 있고 서버 점검 권한 없이도 프로젝트 멤버가 사용할 수 있다.
- 이슈와 서버 연결은 같은 저장 요청으로 반영한다. 존재하지 않는 자산, 삭제된 자산의 신규 연결, 서버 외 자산, 중복 ID는 이슈 생성 전에 거절한다. 이슈 상세의 `작업 대상 서버 연결` / `서버 변경`에서 기존 이슈의 연결을 추가·변경·해제하고 변경 이력에 서버 이름을 남긴다.
- 이슈의 대상 서버와 `서버 점검에 추가`의 대상을 함께 사용한다. 서버가 없으면 공통 점검을 명시적으로 선택한다. 점검 연결 실패 후 대상 서버를 바꿔 재시도하면 이미 생성된 이슈의 서버 연결도 갱신하고 이슈를 다시 생성하지 않는다.
- 자산의 `운영 이력`에는 `스케줄 이슈` 종류로 제목·이슈 번호·진행 상태·일정·담당자를 표시한다. 항목을 누르면 현재 이슈를 팝업으로 열고 수정·닫기 후 자산 탭을 유지하며 이력을 갱신한다. 연결 해제 또는 이슈 삭제 시 일반 이슈 항목은 목록에서 제외한다.
- 동일 자산에 연결된 이슈가 진행 가능한 월간 점검에도 있으면 점검 기록으로 표시해 일반 이슈 중복 행을 줄인다. 과거 완료 스냅샷·이월·제외 회차만 있는 경우에는 일반 이슈도 표시해 다시 열린 이슈가 숨겨지지 않도록 한다. 서버 점검 권한이 없으면 열람 가능한 일반 이슈가 그대로 표시된다. 다른 자산의 점검 회차 때문에 이 자산의 이슈가 숨겨지지 않는다.
- 일반 이슈 이력·건수는 스케줄 관리 권한과 프로젝트 멤버십을 모두 확인한다. 자산 검색은 프로젝트 멤버십을 확인하고 최소 정보만 반환하며 자산 상세로 이동하는 링크는 자산 권한이 있을 때 제공한다. 기존 SR 전용 이슈 조회 경로는 프로젝트 비멤버에게 새 서버 연결 정보를 노출하지 않는다.

## 저장 및 API

`form_entries.asset_ids`에 서버 ID 목록, `linked_assets`에 최소 자산 정보 스냅샷을 저장한다. 조회 시 현재 이름/IP와 삭제 여부를 반영한다. `data` 및 Markdown에는 연결 정보를 넣지 않는다. `asset_ids + created_at` 인덱스는 시작 시 생성된다.

운영 메모는 별도 `asset_notes` 컬렉션에 저장한다. `asset_id`, `content`, `occurred_on`, 작성자 ID·이름, 등록·수정 시각, `version`, `is_deleted`, `client_id`를 보관한다. 자산별 등록일 인덱스와 `(asset_id, client_id)` 고유 인덱스는 시작 시 생성된다.

- `POST /form-entries`, `PATCH /form-entries/{id}`: 선택적 `asset_ids`. PATCH에서 생략하면 기존 연결 유지, 빈 배열이면 해제.
- `GET /form-entries/asset-options?search=...`: 작업 관리 권한으로 최소 서버 정보를 검색한다.
- `GET /form-entries/by-asset/{id}?offset=0&limit=20`: 작업 관리 권한으로 연결된 모든 작업 관리 문서 이력을 최근 등록순으로 조회한다.
- `/job/forms/{templateId}?entryId={entryId}`: 문서 상세 직접 이동.
- `GET /assets/{id}/work-history?offset=0&limit=20`: 권한에 맞는 문서·이슈·점검·운영 메모를 합쳐 정렬·페이지 나눔한다. 항목의 `type`은 `document`, `issue`, `inspection`, `note`이며 점검 항목 ID는 `이슈ID:점검월`이다. 페이지 내 점검 기록만 현재 이슈·자산과 병합 조회한다.
- `GET /pm/projects/{projectId}/asset-options?search=...`: 프로젝트 멤버가 연결 가능한 서버를 검색한다.
- `POST /pm/projects/{projectId}/issues`, `PATCH /pm/projects/{projectId}/issues/{issueId}`: 선택적 `asset_ids`를 저장하고 `linked_assets`로 현재 자산 이름/IP·삭제 여부를 반환한다. PATCH에서 생략하면 유지, 빈 배열이면 해제한다. 삭제된 기존 연결은 유지·해제할 수 있다. `pm_issues.asset_ids + created_at` 인덱스는 시작 시 생성한다.
- `POST /assets/{id}/notes`: `content`, `occurred_on`, `client_id`로 운영 메모 등록.
- `GET /assets/{id}/notes/{noteId}`: 운영 메모 상세와 수정 가능 여부 조회.
- `PATCH /assets/{id}/notes/{noteId}`: `content`, `occurred_on`, `version`으로 수정.
- `DELETE /assets/{id}/notes/{noteId}`: 본문의 `version`으로 삭제.

작업 관리(`job`) 권한 또는 관리자는 연결을 설정하고 이력을 조회할 수 있다. 실제 자산 상세 이동은 자산(`asset`) 권한이 있을 때 제공한다. 기존 문서 조회·작성 권한 규칙은 그대로 사용한다.

## 검증

`WORK_DOCUMENT_TEST_MONGO=1 python -m unittest discover -s tests -p test_work_document_assets.py -v`

`WORK_DOCUMENT_TEST_MONGO=1 python -m unittest discover -s tests -p test_asset_notes.py -v`

`WORK_DOCUMENT_TEST_MONGO=1 python -m unittest discover -s tests -p test_issue_assets.py -v`

실제 MongoDB를 사용하되 UUID 접두사가 있는 테스트 컬렉션과 임시 문서 디렉터리만 생성하고 정리한다. 모든 작업 문서 종류와 새 양식의 연결, 양식 이름 변경, 반입신청서 요약, 양방향 조회, 연결·해제, 삭제 자산·문서·양식, 동시 수정, 권한, 검색, 혼합 이력 페이지 나눔 및 본문·원본 파일 보존을 검증한다.

운영 메모 테스트는 직접 등록, 중복 요청, 입력 검증, 작성자·관리자 권한, 자산 간 분리, 수정·삭제 충돌, 삭제 자산 처리, 문서 권한 필터링 및 통합 페이지 나눔을 검증한다.

점검 통합 테스트는 메뉴·프로젝트 권한, 회차별 대상 분리, 공통 작업 제외, 과거 완료 스냅샷, 이월·제외 사유, 삭제된 이슈·자산 및 세 종류가 섞인 안정적인 페이지 나눔을 검증한다.

이슈 연결 테스트는 선택적 다중 연결, 검증 실패 시 원자성, 연결 유지·해제, 삭제 자산, 검색·프로젝트·메뉴 권한, 최소 정보, 변경 이력, 점검 중복 제거 및 네 종류가 섞인 페이지 나눔을 검증한다.
