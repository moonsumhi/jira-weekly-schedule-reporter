**월간 서버 점검 보고서 기획안**

작성일: 2026-09-17. 상태: 제안. 이 문서는 기획이며 기능 구현을 의미하지 않는다.

월간 작업에서 선택한 월을 기준으로 서버 자원 측정 결과, 이상 항목과 조치 내역, 예정했던 작업과 실제 수행 결과를 모아 보관·출력 가능한 보고서를 만든다. 사용자는 자동으로 채워진 내용을 검토하고 작업 결과와 종합 의견을 보완한다. 기본 산출물은 웹 보고서와 인쇄용 PDF다.

현재 `InspectionTasksPage.vue`의 `점검 보고서` 버튼은 `/inspection/health-summary`로 이동한다. 자원 측정 결과는 `health_reports`, 서버별 조치 메모·이미지는 `health_actions`, 월별 작업 회차는 `inspection_tasks`, 현재 이슈는 `pm_issues`에 있다. 기존 자원 데이터에 CPU·RAM·Swap 측정값, 파일시스템별 디스크 사용량, H/W·보안 점검, 서비스 확인, 점검자·시간·종합 의견이 포함되어 있다. 월별 작업에는 상태·대상·담당자·이월/제외 사유가 있지만 회차별 수행 결과를 작성하는 전용 필드는 없다.

**사용 흐름**

1. 서버 점검 → 월간 작업에서 월을 선택하고 `점검 보고서`를 누른다.
2. 해당 월과 작성 범위에 맞는 기존 보고서가 있으면 보고서를 연다. 없으면 생성 미리보기를 보여준다.
3. 미리보기를 열면 해당 월과 직전 월의 가장 최근 점검 자료를 자동으로 불러와 비교한다. 자료의 점검일·업로드 시각, 자원 수집 서버 수, 작업 수, 자료 미등록·자산 연결 미확인 항목을 표시한다. 자료 선택·별도 확인 버튼 없이 준비된 내용으로 초안을 만든다. 자산 호스트명을 수정하고 돌아오면 미리보기에 반영한다.
4. `초안 만들기`로 자동 집계한 보고서를 저장한다. 작업 결과·특이 조치·종합 의견을 보완한다.
5. 초안에서 `최신 자료 반영`을 누르면 변경된 자원 자료·작업 상태를 확인한 뒤 반영한다. 직접 쓴 의견과 작업 결과를 덮어쓰지 않는다.
6. `보고서 확정` 시 해당 시점의 데이터를 보존한다. 확정본은 웹에서 확인하고 PDF로 저장한다. 수정이 필요하면 새 개정본을 만들고 이전 확정본도 보관한다. 별도 결재 단계는 1차 범위에 넣지 않는다.

월간 작업의 검색어·내 작업·상태 탭·특정 서버/이슈 필터는 보고서 범위에 자동 적용하지 않는다. 보고서를 생성할 때 프로젝트를 다시 선택하지 않으며, 선택 월에 서버 점검으로 등록된 작업을 프로젝트 소속과 관계없이 자동으로 포함한다. 관련 프로젝트 목록은 보고서 본문과 인쇄물에 표시하지 않으며 접근 권한을 제한하는 조건으로도 사용하지 않는다. 기존 보고서의 자료 갱신은 저장된 프로젝트 범위를 유지한다. 같은 월이라도 범위가 다른 기존 보고서는 구분한다.

누락·미완료 항목이 있는 보고서를 열면 해당 보고서에 저장된 항목과 건수를 확인 팝업으로 안내한다. 목록에서 열거나 주소로 직접 열 때 동일하게 동작하며, 내용 수정·저장이나 인쇄 시에는 다시 열리지 않는다. 닫은 뒤에는 상단 `확인할 항목`으로 다시 볼 수 있다. 자동 안내 목록과 미작성 안내 문구는 본문·인쇄·PDF에 포함하지 않는다. 직접 작성한 내용은 `추가 확인 사항`에 표시한다. 선택 항목이므로 비워 두어도 확정할 수 있으며, 미작성 안내나 자동 작업 목록을 본문에 넣지 않는다.

**보고서 구성**

| 순서 | 내용 | 자동 작성 | 사람이 보완할 내용 |
|---|---|---|---|
| 1. 점검 개요 | 보고서명, 점검 월·실제 점검일, 작성자, 생성·확정 시각, 프로젝트 범위, 자료 기준 | 월·작성자·출처·집계 | 점검 목적, 종합 의견, 필요 시 실제 점검일 정정 |
| 2. 결과 요약 | 자원 수집 서버 수, 주의·위험 서버 수, 자료 미수집 수, 완료·미완료·이월·제외 작업 수 | 범위에 맞는 수치 | 주요 성과·남은 문제를 설명하는 짧은 의견 |
| 3. 자원 사용량 및 조치 내역 | 확인이 필요한 서버별 측정값·전월 대비 변화, H/W·보안·서비스 이상, 조치 내용·상태·증빙을 한 표에 표시 | 측정값과 저장된 기준, 점검 결과, 조치 기록으로 분류 | 조치 내용과 후속 확인 계획 |
| 4. 월간 작업 수행 결과 | 이슈 번호·제목, 대상 서버/공통, 담당자, 계획 일정, 수행 결과, 상태 | 회차·이슈·일정·기존 결과 | 회차별 작업 결과와 실제 수행일 |
| 5. 추가 확인 사항 | 보고서 작성자가 필요할 때 직접 입력한 내용 | 없음 | 추가로 확인할 내용이나 전달할 사항 |
| 부록 | 전체 서버별 상세 자원, 파일시스템별 디스크, H/W·보안·서비스 체크, 선택한 증빙 | 원본 자료에서 구성 | 부록 포함 범위 선택 |

첫 페이지는 핵심 수치와 종합 의견을 읽는 데 집중한다. 이후 자원 표와 작업 결과 표를 두고 상세 자료는 부록으로 분리한다. 본문 표에 긴 이슈 설명이나 댓글 전체를 넣지 않는다. 웹에서는 서버·이슈를 눌러 근거를 확인할 수 있고, PDF에는 읽을 수 있는 이름·이슈 번호와 선택한 증빙을 포함한다.

**서버 자원 수치 규칙**

- 자원 사용량과 조치 내역은 하나의 표로 합친다. 주의·위험 기준 이상, 측정값 누락, H/W·보안·서비스·로그 이상, 미완료 조치가 있는 서버만 본문에 표시한다. 실제 내용이 있는 Excel 조치 사항도 등록된 완료 조치가 없으면 확인 대상으로 포함한다. `-`, `없음`, `N/A` 등 빈칸 대용 값과 정상 서버의 완료 이력만으로는 본문에 추가하지 않는다.
- 표는 서버/IP, 확인 사항, 조치 내역으로 구성한다. 확인이 필요한 자원 수치와 전월 대비 변화를 표시하고 하드웨어 등 이상 항목은 중복 없이 함께 넣는다. 조치 칸에는 점검표 기록, 수동 등록 내용, 처리 상태, 작성자·수정일, 증빙 이미지를 표시한다. 대상 서버를 식별하지 못한 미완료 조치는 같은 절 하단에 별도로 표시하되 서버 수에는 더하지 않는다.
- 본문에 전체 서버 수, 확인 필요 서버 수, 특이사항 없는 서버 수를 요약한다. 웹의 `전체 서버 보기`에서는 모든 측정값과 완료 조치 이력을 확인할 수 있다. 펼친 상태로 인쇄해도 본문에는 확인할 서버만 출력한다. `상세 점검표 포함`을 선택하면 전체 서버의 측정값, 전월 대비 변화와 조치 내역·증빙도 부록에 출력한다. 저장된 스냅샷과 원본 데이터는 변경하지 않는다.
- 부록은 서버별 구역으로 구분한다. 호스트명·IP·운영체제·점검자·점검 시간을 상단에 표시하고 CPU·RAM·디스크 핵심 수치, 파일시스템별 사용량, 하드웨어·보안·서비스 점검, 점검 의견, 조치 내역 순서로 배치한다. 웹에서는 서버 바로가기를 제공하고, 모바일에서는 표와 메타 정보를 좁은 화면에 맞춰 정렬한다. PDF는 서버마다 새 페이지에서 시작하며 긴 표는 머리글을 반복하고 내용이 여러 페이지에 걸쳐 이어지도록 한다.
- 수치에는 측정 기준일을 표시한다. 현재 Excel 데이터는 점검 시점의 측정값이므로 월평균·월최대처럼 표시하지 않는다.
- 서버별 자원 수치는 해당 월에 가져온 측정값 하나로 표시한다. 기존 import의 `before_*`/`after_*` 필드는 호환성을 위해 유지하되 화면에서 점검 전후의 두 시점으로 해석하지 않는다. 기존 대표값 선택 순서는 유지하고 별도 측정값을 만들지 않는다. 상세 값이 없고 요약에만 값이 있으면 `요약 수치`로 구분한다. 비교는 전월의 측정값과만 한다.
- 디스크는 가장 사용률이 높은 실제 파일시스템을 대표 값으로 쓰고 경로를 함께 표시한다. `Total`과 개별 파일시스템 최대 사용률을 혼용하지 않는다. 원본에 상세 파일시스템이 없으면 요약값과 그 출처를 표시한다. 존재하지 않는 디스크 전후 측정값은 만들지 않는다.
- 기본 자원 기준은 현재 UI와 같은 80% 이상 주의, 90% 이상 위험으로 제안한다. 수치 기준과 기준 버전을 보고서에 남긴다. 한 서버에 여러 이상 항목이 있어도 위험 서버 수는 서버별 한 번만 집계하고, 이상 항목 수는 별도로 표시한다.
- 자료 없음·형식 오류·측정 제외·N/A는 정상이나 0으로 집계하지 않는다. 자원 수치만으로 서버 전체를 정상 판정하지 않는다. H/W NG, 보안·서비스 확인 결과, 로그 오류, 조치 상태는 별도로 표시한다.
- 비교는 선택한 보고서 월과 직전 월의 최신 점검 자료에서 같은 서버·같은 지표끼리 한다. 최신 순서는 점검일, 업로드 시각 순이다. 자료 기준일을 함께 표시하고 사용률 변화는 %p로 표기한다. 직전 월 자료가 없으면 더 오래된 자료나 같은 달 자료로 대체하지 않으며, 자료 부재 또는 서버 동일성 미확인 시 비교 없음으로 표시한다.
- 대상 서버 수, 자원 자료가 있는 서버 수, 월간 작업에 연결된 서버 수를 구분한다. 자산 목록의 모든 서버를 실제 점검 완료 서버로 간주하지 않는다.

**자산과 측정 자료 연결**

월간 작업은 자산 ID를 사용하지만 Excel 자료는 호스트명·IP를 사용한다. 두 자료를 서버별로 합치기 위한 연결 정보가 필요하다.

- 자산의 호스트명과 측정 자료의 호스트명이 양쪽에서 유일하게 일치하면 자동 연결한다. 대소문자·앞뒤 공백·마지막 마침표를 정규화한다. IP는 자동 연결 조건이 아니다.
- 호스트명이 다르면 자산에서 수정한다. 동일 IP의 자산이 하나이면 해당 자산 확인 링크를 제공한다. 자산을 수정한 후 돌아오거나 `다시 확인`을 누르면 미리보기에 반영한다. 중복된 호스트명은 자동 연결하지 않는다.
- 자동 연결되지 않은 예외 항목만 해당 월·자료에 대해 직접 연결할 수 있다. 새 영구 매핑을 저장하지 않으며, 기존 영구 연결도 재사용하지 않는다. 보고서 스냅샷에는 선택 결과를 보존하되 다음 달·다른 업로드 자료에는 넘기지 않는다. 같은 보고서·같은 자료의 갱신에서는 기존 예외 연결을 유지하거나 해제할 수 있다.
- 연결되지 않은 측정 행도 보고서에서 누락하지 않고 확인 대상으로 표시한다. 자원 자료가 없는 작업 대상 서버는 `자원 자료 미등록`으로 표시한다.
- 확정 보고서에는 당시 자산 이름·IP와 연결 상태를 보존한다. 이후 자산명 변경·삭제로 예전 보고서가 달라지지 않게 한다.

**월간 작업 집계와 작업 결과**

- 해당 월에 등록된 회차는 완료·미완료·이월·제외를 모두 포함한다. 미완료 탭에 보이는 작업만 가져오지 않는다.
- 전월에서 이번 달로 실제 이월된 회차는 이번 달 작업으로 집계하고 원래 월을 표시한다. 이전 달에 남아 있는 미완료 작업은 별도 참고 목록으로 보여주며, 단지 화면에 표시된다는 이유로 당월 수행 건수에 더하지 않는다. 이번 달 실제 수행한 작업은 당월 회차 또는 당월 수행 기록에 연결해야 한다.
- 완료는 기존 기준대로 `DONE`만 인정한다. `IMPLEMENTED`를 포함한 나머지 이슈 상태는 미완료로 분류한다. `ROLLED`, `EXCLUDED` 회차는 각각 이월·제외로 분리해 한 회차가 여러 상태에 중복 집계되지 않게 한다.
- 당월 계획 건수 = 완료 + 미완료 + 이월 + 제외. 기본 계획 대비 완료율은 `완료 / (당월 계획 - 제외)`로 계산하고 식을 표시한다. 이월도 계획 대비 미완수이므로 분모에 포함한다. 분모가 0이면 `해당 없음`이다.
- 여러 서버에 연결된 이슈는 전체 작업 건수에서 회차당 한 번만 센다. 서버별 보기에는 각각 나타날 수 있으므로 서버별 행 수를 전체 작업 수로 더하지 않는다. 공통 작업은 별도 구역에 둔다.
- 회차별로 `작업 결과`, `실제 수행일`, `결과 작성자·시각`, 선택적 `증빙`을 저장한다. 이슈의 계획/설명과 실제 수행 결과를 구분한다. 예: `로그 보관 기간 90일 → 30일 변경, 서비스 재기동 및 정상 동작 확인`.
- 월간 작업에서 결과를 남기고 보고서에서도 같은 결과를 편집할 수 있게 해 재입력을 줄인다. 상태가 완료여도 결과가 비어 있으면 `결과 미작성`으로 표시한다. 상태만 보고 수행 내용을 만들어 채우지 않는다.
- 점검에서 발견한 서버 이상에 대한 조치와 PM 작업을 연결할 수 있게 한다. 자동으로 같은 작업이라고 단정하지 않고 명시적으로 연결한 경우에만 서로 참조한다. 기존 서버별 조치 메모·이미지와 이월 사유는 가져와 활용한다. 조치 증빙 이미지는 기본으로 포함하며 생성 화면에서 별도로 선택받지 않는다.
- 보고서 의견 수정이나 `최신 자료 반영`이 PM 상태·담당자·마감일을 변경하지는 않는다. 작업 상태 변경·이월은 명시적인 작업 관리 기능에서 수행한다.

**화면과 보관 방식**

전용 경로는 `/inspection/monthly-reports`와 `/inspection/monthly-reports/{id}`로 제안한다. 월간 작업의 `점검 보고서` 버튼은 선택한 월을 이 경로로 전달한다. 기존 요약 화면은 자원 조회·Excel 업로드 용도로 유지하고, 화면 안에서 사용하는 ‘업로드된 보고서’와 새 ‘월간 점검 보고서’의 표현을 구분한다.

편집 화면은 큰 입력 폼 대신 보고서 미리보기를 중심으로 구성한다. 상단에 점검 월·범위·초안/확정·버전을 표시하고 `초안 저장`, `최신 자료 반영`, `보고서 확정`, `PDF 저장`을 둔다. 수정 가능한 종합 의견과 작업 결과에만 편집 동작을 제공한다. 인쇄 화면에는 작업 버튼·검색·불필요한 배지를 제거하고 표 머리글 반복, 페이지 나눔, 페이지 번호를 적용한다.

저장 객체는 기존 Excel 측정 자료와 분리한 `monthly_inspection_reports`로 제안한다. 월·범위·상태·개정번호·작성자·작성/확정 시각과 함께 자료 출처, 자산 연결, 정규화한 자원 값, 당시 작업/조치/결과, 집계 기준, 종합 의견을 보관한다. 원본 참조 ID뿐 아니라 보고서 본문을 재현할 값과 필요한 증빙도 보존한다.

동일 날짜 Excel 업로드는 현재 원본 자료를 갱신하므로, 원본 ID만 저장하면 과거 보고서가 바뀔 수 있다. 초안에도 자료를 가져온 기준 시점을 표시하고 확정본은 고정한다. 원본 변경 시 자동 덮어쓰지 않고 변경 안내와 갱신 미리보기를 제공한다. 동시에 수정한 초안은 버전 충돌을 알려 작성 내용을 보존한다. 생성 중 실패나 재시도로 같은 초안이 중복 생성되지 않게 한다.

자원 자료가 없어도 초안은 만들 수 있다. 확정 시 선택한 범위에 대한 자료 부재·미연결 자산·결과 미작성·미완료 작업을 한곳에서 검토하고, 누락 사유를 명시한 상태로 보존할 수 있게 한다. 불완전한 자료를 정상 점검 완료로 표현하지 않는다. 과거 월에 첫 보고서를 만들 때는 당시 확정본이 아니라 현재 자료로 재구성한 보고서임을 표시한다. 과거 당시 상태를 복원할 수 없는 항목은 그 한계를 드러낸다.

보고서 API와 내보내기는 서버 점검 메뉴 권한을 기준으로 접근을 허용한다. 해당 권한이 있는 사용자와 관리자는 프로젝트 소속과 관계없이 모든 보고서를 조회하고 초안의 의견·참여자·작업 결과를 편집하며 자료 갱신·확정·개정본 작성을 할 수 있다. 사용자별 프로젝트 멤버십 때문에 본문·건수가 달라지거나 갱신 때 작업이 누락되지 않게 한다. 확정본은 보존하며 수정 시 개정본을 작성한다. 보고서에 포함된 작업 결과는 보고서 전용 API에서 회차 포함 여부를 검증한 뒤 월간 작업과 동일한 결과 저장소에 반영한다. PM 이슈 자체의 조회·수정 권한과 기존 내부망 쓰기 정책은 유지한다. 별도 공개/외부 공유 기능은 1차 범위에서 제외한다.

자산의 운영 이력에는 해당 서버가 포함된 확정 보고서를 연결해 점검 당시 기록을 찾을 수 있게 하는 방향을 제안한다. 보고서 안에서 서버와 관련 작업을 함께 확인할 수 있고, 자산에서 열면 팝업으로 표시해 닫았을 때 기존 자산 화면을 유지한다. 자산 운영 이력에 점검 추가 버튼을 다시 넣지 않는다.

- 자동 검증: `INSPECTION_TEST_MONGO=1`로 실행하는 점검 관련 테스트 34개(임시 컬렉션), 프런트엔드 빌드, 모의 API를 사용한 브라우저 작성·확정·개정·권한·모바일·인쇄 검증. 서버 40대와 긴 작업 결과 및 상세 부록의 PDF도 확인했다.
- 실행 중인 Docker 서비스는 소스를 직접 마운트하지 않으므로 적용 시 프런트엔드·백엔드 이미지를 재빌드해야 한다. 백엔드 시작 시 보고서 인덱스와 메뉴 항목을 준비한다.

**참여자별 역할·수행 업무 (2026-09-17)**

보고서의 `참여자 및 역할 → 참여자 관리`에서 백오피스 사용자를 이름·소속·이메일로 검색하여 추가한다. 점검 총괄, 서버·자원 점검, 작업 수행, 서비스 확인, 결과 검토, 기타 역할을 여러 개 선택할 수 있다. 참여자를 선택하면 보고서에 포함된 당월의 활성 점검 작업 중 담당자 ID가 일치하는 이슈를 `담당 업무 · 자동 연결`로 표시한다. 완료뿐 아니라 진행 중인 담당 업무도 포함하며 현재 상태를 함께 표시한다. 제외·다음 달 이월·이전 달 미완료 참고 작업은 자동 연결하지 않는다. 역할과 수행 업무는 직접 작성할 수 있고 `추가로 참여한 작업`에서 다른 당월 작업도 수동 연결할 수 있다.

이름·소속·역할·수행 업무·관련 작업을 본문과 PDF에 함께 표시한다. 수동 연결(`tasks`)과 자동 담당 업무(`assigned_tasks`)는 분리 저장하며 본문에서는 같은 이슈를 한 번만 표시한다. 자료 갱신 시 새 스냅샷의 담당자에 맞춰 자동 연결을 다시 계산하되 수기 내용·역할·수동 연결은 유지한다. 이슈 담당자가 바뀌어도 보고서 자료 갱신 전에는 기존 기준을 유지한다. 참여자 등록 시점의 이름과 소속을 보존하고, 사용자 변경·삭제로 확정본을 바꾸지 않는다. 기존 초안의 참여자도 저장된 작업 스냅샷으로 자동 연결을 제공하며 확정본 조회는 보존된 내역만 사용한다. 개정본에는 기존 참여 내역과 스냅샷을 복사한다. 수동 연결한 작업이 자료 갱신 후 사라져도 수동 연결 기록은 유지한다.

서버 점검 메뉴 권한을 적용하며 보고서에 포함된 프로젝트의 멤버십은 요구하지 않는다. 신규 참여자는 이용 가능한 백오피스 사용자만 선택할 수 있으며 중복 사용자·역할·작업과 보고서 밖 작업 연결을 검증한다. 참여자로 등록하는 동작은 프로젝트 권한이나 이슈 담당자를 변경하지 않는다. 동시 수정으로 저장에 실패하면 작성 내용을 유지한다.

참여 기능에 대한 8개 테스트를 추가하여 점검 관련 테스트 총 42개를 통과했다. 기존 보고서에 참여 필드가 없는 경우, 계정이 삭제된 참여 기록, 확정본·개정본 분리, 사용자 검색과 PDF 출력도 확인한다.

**보고서 공동 편집 권한 (2026-09-17)**

프로젝트 멤버십 대신 서버 점검 메뉴 권한을 적용했다. 프로젝트 소속이 없는 사용자도 모든 보고서를 조회하고 초안의 의견·참여자·작업 결과를 편집하며 자료 갱신·확정·개정본 작성을 할 수 있다. 자료 갱신 시 저장된 보고서 범위의 작업을 유지하고, 프로젝트가 삭제된 보고서도 조회·갱신할 수 있다. 작업 결과 API는 보고서에 포함된 이슈와 회차만 허용하며 공통 결과 버전 검사로 동시 수정을 보호한다. 자동 자료 비교를 포함한 점검 테스트 총 49개를 통과했다.

**보고서에서 항목별 직접 수정 (2026-09-17)**

초안의 자원 표와 상세 부록에 `조치 작성/수정`, 월간 작업에 `수정` 버튼 하나, 추가 확인 사항에 `+` 추가 버튼과 항목별 `수정/삭제`를 제공한다. 월간 작업의 `수정`에서는 작업 결과·작업일·추가 작업 계획을 함께 편집한다. 항목 옆 버튼으로 편집 창을 열고 저장하면 보고서를 떠나지 않고 반영 내용을 확인할 수 있다. 위에 표시한 서버를 제외한 나머지 서버 표의 펼친 상태도 유지한다. 수정 버튼과 편집 창은 인쇄/PDF에 표시하지 않는다.

조치 내용·진행 상태·증빙 이미지는 해당 보고서의 원본 자원 점검 데이터에 저장하고, 보고서에는 해당 조치만 반영한다. 측정값·비교 자료·이슈 상태는 이 동작으로 갱신하지 않는다. 기존 증빙은 편집 시 유지하며, 원본 서버/조치가 삭제되거나 호스트명이 중복되어 대상을 구분할 수 없으면 저장을 막는다. 보고서 버전과 원본 조치 변경 여부를 검사해 다른 작성자의 내용을 덮어쓰지 않는다. 원본 저장 직후 보고서가 확정되거나 자료가 바뀌면 확정본을 유지하고 반영하지 못한 사실을 안내한다.

작업별 추가 계획은 월간 작업의 결과 필드를 공유하며 계획만 수정할 때 기존 작업 결과와 수행일을 유지한다. 보고서의 추가 확인 사항은 해당 보고서에 저장한다. 취소·이동 시 미저장 내용을 확인하고 저장 실패 시 입력을 유지한다. 확정본에는 직접 수정 버튼을 제공하지 않으며 기존 `수정본 작성`을 이용한다.

**선택 입력하는 추가 확인 사항 (2026-09-17)**

`추가 확인 사항`에는 보고서 작성자가 직접 입력한 내용만 항목별로 표시한다. `+`로 한 항목씩 추가하고, 각 항목을 수정하거나 확인 후 삭제한다. 내용이 빈 항목은 저장하지 않는다. 미완료·이월 작업과 이전 달 작업 목록을 자동으로 넣지 않는다. 기존 단일 `limitations` 내용은 `legacy` ID의 첫 항목으로 읽어 그대로 표시한다. 조회만으로 DB나 확정 보고서를 변경하지 않는다. 목록을 저장할 때 `additional_notes` 배열로 전환하고 구형 필드는 비워, 마지막 항목을 삭제해도 옛 내용이 다시 나타나지 않도록 한다. 작업별 추가 계획은 해당 `월간 작업 결과` 안에서 표시·수정하며 보고서의 추가 확인 사항과 별개다.

초안의 `내용 추가/수정`으로 자유롭게 작성하고, 내용을 비워 저장하면 제거한다. 입력하지 않아도 보고서를 확정할 수 있다. 비어 있는 영역은 초안 화면에서만 표시하고 확정본·인쇄·PDF에서는 생략한다. 누락·미완료 항목 안내 팝업은 유지하되 추가 확인 사항을 작성하도록 강제하지 않는다.


### 추가 확인 사항 목록 저장

- `PUT /monthly-inspection-reports/{id}/notes`는 보고서 버전과 `{id, content}` 목록을 받는다. 내용은 항목당 최대 5,000자, 목록은 최대 100개다. 중복 ID와 빈 내용을 거부한다.
- 보고서 버전 조건부 갱신으로 동시 추가·수정·삭제를 보호한다. 충돌 시 작성 중인 내용을 유지하고 오류를 표시한다. 종합 의견, 작업 결과, 자원 자료에는 영향을 주지 않는다.
- 보고서 내용 수정 창은 제목·점검일·목적·종합 의견·부록만 다룬다. 추가 확인 사항은 해당 절의 항목별 버튼으로 편집한다. 구형 클라이언트가 단일 텍스트로 새 목록을 덮어쓰려 하면 충돌을 반환한다.
- 점검 자료 새로 불러오기·작업 결과 반영·수정본 작성은 목록을 유지한다. 확정 보고서는 편집을 차단하고 당시 목록을 보존한다. 인쇄/PDF에는 순서가 있는 목록만 표시하고 추가·수정·삭제 버튼은 숨긴다.
- `tests/test_monthly_inspection_reports.py`에서 목록 CRUD, 권한·입력 검증, 동시 변경, 기존 문서 보존, 초안 갱신 및 확정본·수정본 분리를 검증한다.
