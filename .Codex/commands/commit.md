# commit

저장소 변경 사항을 티켓 번호와 함께 커밋하고 현재 브랜치의 origin으로 push한다.

## 사용법

```text
/commit BACKOFFICE-118 작업 관리 변경 사항 반영
/commit SR-2026-0205 SR 화면 수정
```

## 실행 규칙

1. `$ARGUMENTS`의 첫 번째 토큰을 티켓 번호로 사용한다.
2. 티켓 번호가 없으면 커밋하지 않고 사용자에게 티켓 번호를 요청한다.
3. `git status`와 staged diff를 확인한다.
4. 현재 작업과 관련된 추적 파일만 스테이징한다. 다음 파일은 명시적으로 요청하지 않는 한 스테이징하지 않는다.
   - 압축·백업 파일 (`*.zip`, `*.tar`, `*.bundle`)
   - 개인 설정 파일 (`.env`, `.claude/settings.local.json` 등)
   - 생성된 데이터와 로그
   - 작업과 무관한 서브모듈 변경
5. 프론트엔드 파일이 변경되었으면 커밋 전에 아래 검사를 실행한다.

   ```text
   cd frontend/optool
   npm run lint
   npm run build
   ```

   린트나 빌드가 실패하면 원인을 수정한 뒤 다시 검사하고, 성공 전에는 커밋하지 않는다.
6. 커밋 메시지는 다음 형식을 사용한다.

   ```text
   [TICKET] type(scope): 변경 내용
   ```

   `type`은 변경 성격에 따라 `feat`, `fix`, `refactor`, `chore` 중 선택한다.
7. 커밋 전에 staged 파일 목록과 커밋 메시지를 사용자에게 보여주고, 이미 작업 범위 승인이 있으면 계속 진행한다.
8. 커밋 후 `git push origin <현재 브랜치>`를 실행한다.
9. 커밋 해시와 push 결과를 사용자에게 보고한다.

## 안전 규칙

- 티켓 번호가 없는 커밋은 만들지 않는다.
- 사용자가 요청하지 않은 파일을 삭제하거나 되돌리지 않는다.
- 충돌, 인증 실패, 빌드 실패가 발생하면 원인을 보고하고 임의로 강제 push하지 않는다.
- `--force` push는 사용자가 명시적으로 요청한 경우에만 수행한다.
